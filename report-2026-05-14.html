進度摘要

在 Jetson Nano 上部署步態辨識門禁系統，完成 ultralytics、torch、torchvision、OpenCV 等核心套件安裝。針對 Jetson 內建 Python 3.6 與安裝環境 Python 3.8 共存的版本錯置問題，逐一修正程式中 __future__ annotations、新式型別標註與 | 聯合型別等不相容語法。另排查 CSI 鏡頭驅動失敗的根本原因為 pip 安裝之 OpenCV 未含 GStreamer 支援，目前以系統套件方式重新部署中。

一、專案目錄結構

於 Jetson Nano 建立 ~/gait_system/ 工作目錄，分層存放相機讀取、姿態估計與資料庫等模組：

~/gait_system/ ├── camera.py # CSI 鏡頭讀取 ├── pose.py # YOLOv8 姿態估計 ├── main.py # 主程式（登錄 / 門禁） ├── models/ # 存放 yolov8n-pose.pt └── db/ # 存放步態特徵資料庫

二、套件安裝

使用 pip3 安裝 YOLOv8 與影像處理相關依賴，針對 Jetson Nano 網速不穩的情況加上逾時與快取設定：

pip3 install ultralytics opencv-python numpy --timeout 300 --no-cache-dir

遭遇問題與解決方式

問題 原因 解決方式
Defaulting to user installation site-packages 無寫入權限 加上 --user 或 sudo pip3
socket.timeout: Read timed out 網速僅約 18 kB/s，下載 matplotlib 逾時 加 --timeout 300 --no-cache-dir 重試
Hash mismatch 驗證失敗 下載檔案損壞 pip3 cache purge 後重新安裝
安裝到 Python 3.8 但執行用 3.6 系統有兩個 Python 版本共存 統一改用 python3.8 執行所有指令
最終安裝成功套件：ultralytics-8.4.50、torch-2.4.1、torchvision-0.19.1、opencv-python-4.13.0.92、numpy-1.24.4 等。

三、程式碼 Python 3.8 相容性修正

原專案以較新版本 Python 撰寫，部署至 Jetson 環境後需逐項調整型別標註與語法。

問題 1：from __future__ import annotations

原因：Python 3.8 以下不支援此語法。

sed -i '/from __future__ import annotations/d' main.py pose.py camera.py

問題 2：list[...]、dict[...]、tuple[...] 型別標註

原因：Python 3.9 以上才支援內建型別直接作為泛型標註，需改用 typing 模組的 List、Dict、Tuple。

sed -i 's/-> list\[/-> List[/g' main.py pose.py sed -i 's/-> dict\[/-> Dict[/g' main.py pose.py sed -i 's/-> tuple\[/-> Tuple[/g' main.py pose.py sed -i 's/: list\[/: List[/g' main.py pose.py sed -i 's/: dict\[/: Dict[/g' main.py pose.py sed -i '1s/^/from typing import List, Dict, Optional, Tuple\n/' main.py pose.py

問題 3：int | None 聯合型別語法

原因：Python 3.10 以上才支援 | 聯合型別。

sed -i 's/int | None/Optional[int]/g' main.py sed -i 's/str | None/Optional[str]/g' main.py

問題 4：No module named 'dataclasses'

原因：Python 3.6 沒有內建 dataclasses。

解決：執行 pip3 install dataclasses（套件已安裝至 3.8 路徑，後續統一使用 python3.8 執行即可）。

四、CSI 鏡頭問題排查

執行 camera.py 出現 RuntimeError：無法開啟 CSI 攝影機，依序排查可能原因：

嘗試步驟 結果
sudo modprobe nvhost_vi FATAL: Module not found
ls /dev/video* ✅ /dev/video0 存在
gst-inspect-1.0 nvarguscamerasrc Argus EndOfFile 錯誤
sudo systemctl restart nvargus-daemon ✅ Daemon 啟動成功
GStreamer pipeline 測試 ❌ 開啟失敗
確認 OpenCV GStreamer 支援 ❌ GStreamer: NO
根本原因：pip 安裝的 opencv-python 不含 GStreamer 支援，需改用系統內建版本或重新編譯含 GStreamer 的 OpenCV。
