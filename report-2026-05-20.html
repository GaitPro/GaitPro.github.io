進度摘要

本次於 Jetson 平台上完成「步態辨識門禁系統 galt_system」的端到端實測，涵蓋使用者登錄、即時辨識與身分驗證。以 MediaPipe Pose 取代原本的 YOLOv8+TensorRT 流程，搭配 OpenCV（GStreamer）以 1280×720 @ 120 FPS 擷取影像。Alice、Bob 兩位使用者皆成功登錄 32 維步態特徵向量；通行測試中 Bob 分數穩定維持在 0.997～1.000 之間、未知人員以 0.776／0.667 低於門檻被正確拒絕，整體系統行為符合預期。

本次實作依序完成三個階段：

  • 驗證辨識結果：確認已知使用者通行、未知人員拒絕。

八、已知問題與注意事項

8.1 OpenCV / GStreamer 警告

[ WARN ] global cap_gstreamer.cpp:1728 open OpenCV | GStreamer warning: Cannot query video position: status=0, value=-1, duration=-1

此警告為 GStreamer 後端不支援 position query 的已知問題，不影響影像擷取功能。

⚠️ 注意：任何 pip install opencv 相關套件將覆蓋 GStreamer 支援，導致鏡頭無法啟動。

8.2 程式中止（KeyboardInterrupt）

以 Ctrl+C 中止程式後出現 Traceback，為正常手動中止行為，非程式錯誤。MediaPipe 在 graph.wait_until_idle() 階段被中斷，下次啟動可正常執行。

8.3 MediaPipe 限制

  • 由於 Jetson 板無法安裝 PyTorch，改用 MediaPipe Pose 替代 YOLOv8+TensorRT。
  • 效能：預期 30 FPS+ 降至實際 10～15 FPS。
  • 多人場景：目前版本不支援多人同時辨識。
  • 單人進出場景下，10～15 FPS 的效能已足夠運作。

8.4 使用者辨識混淆問題 ⚠️

現象：系統在多使用者情境下，有時未能準確區分不同使用者（如 Alice 與 Bob 被誤認）。

項目 說明
問題描述 不同使用者的步態特徵向量相似度過高，導致辨識結果混淆。
根本原因 登錄週期數（目前 5 週期）不足，採集的步態樣本量偏少，特徵向量代表性不夠。
影響範圍 多使用者環境下辨識準確率下降，誤通行風險提高。
待改善方向 增加登錄週期數，擴大每位使用者的步態樣本量，提升特徵向量的穩定性與區辨性。

九、後續建議

  • 【優先】增加登錄週期數：將目前 5 週期提升至 10～20 週期，增加步態樣本覆蓋率，改善多人辨識準確率。
  • 資料庫擴充：增加更多使用者並測試辨識準確率變化。
  • 門檻調校：根據實際環境調整通行分數門檻（目前約 0.8 以上通行）。
  • 32 維特徵向量優化：可研究升維或改用其他骨架特徵提升辨識率。
  • 多人場景：如需支援，考慮整合人員追蹤（tracking）模組。
  • 保護 OpenCV：在 README 及 requirements.txt 旁加入警告，避免誤裝覆蓋 GStreamer。
